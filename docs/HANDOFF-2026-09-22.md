## 背景（一分钟版）

讨论确定：krystallizer 的会话存储原语统一为 channel 日志（人的聊天与 LLM 对话共用一个容器），agent 上下文是它自己的投影（checkpoint + coverage 增量 + 未读）；消息键用 gravity 打的时间戳（不是 seq）；压缩是启发式策略引擎（缓存时钟 / 50% 预算 / max-gap 分界），参数化 + 决策日志，回归调参推迟；多人模式独立成 ADR（成员身份两层、kind=profile 画像、插话策略）；aura 侧补 timer wheel + cron 原语，gravity 按 channel 一实例。

## 会话产出迁移（ADR-0018 两步存储方案，已落地 2026-09-22）

实现记录迁入 `docs/PLAN.md` Phase 6.6 的 Value representation 条目（[x]，含全部
细节与偏差记录）。要点：

1. **[x] 第 1 步**：`StoreAsVirtual`（base64-in-JSON 桥）删除；mq 表与 actor state
   文档绑一个 okm 引擎（生产 = `FjallStore` "aura_mq" keyspace，测试 = okm
   `TestStore` 真实引擎矩阵——无 aura 侧存储抽象、无 JSON 容器、无自造替身）。
2. **[x] 第 2 步**：actor state = `realm/src/state.rs` 文档模型（registry 模式：
   pkey `InstanceStateKey {type_id, instance_id}`；(type_id, key) → id 走
   `by_key` 文本索引（变长 key 居末，ADR-0005），next id 来自 type_id 上的
   MAX reduce——okm 侧已立 ADR-0023 预置组合子（`MaxKeep`）承接此类用法；
   id 永不复用（unfold = keep）；JSON ↔ `DynamicValue` 只在 `realm/src/value.rs`。
   曾试 SHA-256 key 方案，被否（碰撞 = 静默状态损坏 + 观察面需彩虹表）。
3. 遗留：meta plane（`PersistedActor`）仍 JSON over 旧 SharedStore——单独关注；
   aura-storage crate 的 `InMemoryStore`/`FjallStateStore` 现仅余 meta plane
   消费者，去留待 meta plane 迁移时一并裁决。
