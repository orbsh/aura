# 0015 — 节点身份：一次拨号一个 token，按摘要批准

> **语言 / Languages:** [English](0015-node-identity-a-token-at-the-dial.md) (primary) · [中文](0015-node-identity-a-token-at-the-dial.zh-CN.md)

**Status:** Accepted（2026-09-20）。**2026-11-20 按它现在实现的样子重写** —— 这份记录最初采纳的是每节点独立的 ed25519 密钥对与签名握手，那个设计已经不在；取代它的写在下面，旧的写在《演化》里。已落地：信任模式开关与披露、按摘要的节点登记表与批准端点、拨号上的 token、以及机器绑定（prism ADR-0020）。把记录并入账号认证，待 prism 的账户会话面。

## Context（背景）

effector 拨入 gateway 时声称一个节点别名。两件事必须成立：能到达 gateway 的必须是操作员自己拥有的机器，而控制端必须说得出是哪一台 —— 且不依赖一个跨该用户所有节点共享、可被重放、或存放在任何可被读出之处的秘密。

要保护的资产是**归属**，不是节点的秘密。凭据从不下发，操作使用节点本地的材料，所以冒充者重跑同一个操作什么也得不到。冒充者的收益在控制端：它读到路由给该别名的操作流，它谎报结果，而它的应答作为输入被模型消费。节点身份保护的是拨入者的归属。

节点身份针对的是**不是控制端**的那些主体。控制端按构造就是信任权威：它选择操作、持有 agent、路由每一次调用，节点既无法也不需要约束它。这里要修的是另一个方向 —— 除它以外的任何人也都不必证明任何事。

## Decision（裁决）

### 1. 身份是每节点一个 token，由控制端铸

32 字节随机数，URL 安全的 base64、不带填充；由节点登记表铸出，并且只在铸出它的那次响应里出现一次。它走**拨号**：作为查询参数 —— `/effector/<alias>?token=…` —— 因为 URL 查询不需要转义，而 socket 到达的那一刻是对端唯一一次在被服务之前被应答的机会。

关于 token 的一切都不走帧。一个装进帧里的证明，就是装进每一份会记录帧的日志里的凭据；而连接本身已经带着它了。

### 2. 登记表存摘要，永不存 token

行里存的是 token 的 SHA-256 hex：只比对，不解析。节点 token 本身就是高熵随机数，慢 KDF 在这里买不到任何东西；要紧的是节点表的一份 dump 不是一串钥匙。token 本身活在节点活着的地方 —— 它的配置文件，或者容器形态的 `--token`；effector ADR-0003 §11 让它不落在 argv、也不落在环境变量里，那两处机器上的其他进程都读得到。

### 3. 拨号就是握手；`Register` 只声明形状

没有 challenge，也没有签名。URL 路径就是声称（`/effector/<alias>`），路径上的 token 在 socket 被服务之前核对，而节点的第一帧说的是它**是**什么 —— alias、carriers、class、machine（effector ADR-0006）—— 从不是它知道什么。

gateway 会怎么答，以及答自哪一行：

| 姿态 | 对端出示 | 应答 |
|---|---|---|
| `required` | 没有 token | 拒绝，理由里说明怎么铸一个 |
| `required` | 一个没有任何已批准行的摘要 | `pending` —— 声称自己排队，好让操作员看见这次尝试 |
| `required` | 该别名下已批准的摘要 | `registered` |
| `required` | 已批准、但登记在该别名另一条记录下的摘要 | `conflict` —— 拒绝并上报 |
| `required` | 已批准的摘要，但来自 token 未绑定的机器 | `conflict` —— 拒绝，两台机器都点名（prism ADR-0020） |
| `open` | 任何东西（有没有 token 都行） | `registered`；顶掉活连接的行为会上报 |

### 4. 批准的对象是摘要，动作发生在控制端

控制端 —— 连接平面的 gateway，即 prism —— 保存登记表：`{alias, credential, status, created_at, labels, owner, machine}`，其中 `status` 为 `pending | approved | revoked`。批准就是把一个具体的摘要移到 `approved`；别名始终是人选的名字，不再承担安全语义，因为同名的两个节点靠摘要区分，摘要不符就是 `conflict`，不是接管。

后来有两件事加进了这份记录，它们属于这里：`labels` 是操作员在铸 token 时给这台机器的名字，`owner` 是它们所属的用户（prism ADR-0020）；`machine` 由第一次已批准的注册写入，把 token 绑到那台硬件上（effector ADR-0006）。

### 5. HTTP 接口，以 curl 为先（账号体系出现前的过渡形态）

```
POST   /admin/nodes                    {alias, labels?, owner?} → 铸；token 在这份响应里，只有这一次
GET    /admin/nodes                                             → alias、状态、labels、owner、machine
POST   /admin/nodes/{alias}/approve    {credential?}            → 批准（不带就批唯一那条 pending）
DELETE /admin/nodes/{alias}            {credential?}            → 吊销（行留成 `revoked`）
```

四条端点加一条记录，挂在连接平面上（ADR-0017 §7），于是走 prism 的路由面。等账号体系出现，同一条记录挂到账号下：铸的时候写 `owner`，每个端点都要求登录用户，于是“节点登记表”变成“你的节点”，记录无需迁移。

### 6. 轮换与吊销

一个节点记录一个 token。轮换 = 铸一个新 token 并批准它；此前已批准的记录落到 `revoked` —— 一块墓碑，绝不是静默删除，因为历史就是审计。吊销是同一种状态迁移，作用于该别名的每一条活记录。两者都是操作员（日后是账号所有者）的动作，**永远不是节点自己的动作**。

因为 token 绑到第一次注册它的那台机器（prism ADR-0020），轮换也是给一台机器**改名**的方式：名字随 token 走，硬件身份不随。

### 7. 信任模式是一个显式声明的部署形态开关

认证值多少，等于它背后可达集值多少。在内网、VPN 之后、集群内的控制通道里 —— gateway 只能被操作员自己拉起的机器够到，而这些机器在启动时以可预测的名字自注册 —— 一个 token 守的是网络已经守住的入口。反弹连接同理：隔离网络里的容器拨出去，控制端落在操作员自己这一侧。

所以模式是部署形态的声明，不是假定 —— 它是 prism 网关配置里的 `identity` 字段：

```
{ "identity": "required" }   // 未获批准或不带 token 的对端会被应答，但绝不被服务
{ "identity": "open" }       // 仅凭别名注册：边界就是网络
```

- **该字段没有默认值。** 与声明的 KV 前缀同一个结构理由：一个来者不拒的 gateway 是操作员必须**选择**、并且必须能从配置里读出来的状态，而不是由“值缺席”继承来的状态。
- **`open` 模式的 gateway 在启动时声明自己的姿态**（注册不经认证），于是部署的信任模式体现在它自己的日志里，而不只写在配置文件里。
- **effector 声明同一件事**：带 token 就拨号，不带就空手拨号。空手拨向 `required` 的 gateway，会被应答 `unauthenticated` —— 操作员看得见的错误，而不是静默降级。

**替换纪律是两种模式都保留的规则。** 在 `open` 模式下第二条连接可以接管别名 —— 重启后的容器必须能从自己的陈旧注册手里夺回名字 —— 但接管会作为事件记录，写明别名、旧对端地址与新对端地址。在 `required` 模式下这根本不会发生：已批准的摘要绝不被静默顶掉。静默替换是操作员失去“调用实际去了哪里”这条线索的方式，这在可信网络内部同样成立。

**`open` 模式放弃了什么，直说：** 归属，以及针对同一边界内另一台机器的全部防御。能到达 gateway 的人就能声称任一别名、读取路由给它的操作流、并以它的名义作答 —— 这正是 Context 里点名的收益。当可达集是操作员自己的机器时，这是个正确的取舍；一旦还有别的东西能到达 gateway，它就是错的取舍。对反弹部署而言，算数的是 **gateway 的**可达集，不是节点的：如果控制端本身暴露在开放网络上，`open` 模式意味着任何人都可以声称任何别名，隧道必须终止在一个会做过滤的地方。这个开关不替你做判断 —— 由操作员做，就在那一行能被评审看见的配置里。

## 演化

这份记录最初采纳的是**每节点独立的 ed25519 密钥对**（WireGuard 的编码格式）：节点生成密钥对并打印公钥，操作员批准那把公钥，握手时服务端发一个 nonce，节点在 `Register` 里对它签名。它被放弃，是因为 effector ADR-0003 定下了“授权只发生在拨号那一刻”（§11：*一次拨号一个 token；连接即授权*）。三条理由杀死了签名：

- **证明在帧里旅行。** `Register` 里的签名，就是每一份记录帧的日志里的凭据 —— 恰恰是这个设计本要避免的东西。
- **节点没有好地方放密钥材料。** 容器在启动时被交给凭据；而节点机器上的私钥文件，是一个会丢、要备份、每次重新部署都要轮换的文件。
- **在集群上吊销最终还是要重新铸**，而重新铸的密钥与重新铸的 token，除了活动部件的数量，没有区别。

原样保留、也是这里小节号没有挪动的原因：批准是控制端上的操作员动作（§4）、以 curl 为先的四条端点（§5）、以状态迁移加墓碑表达的轮换与吊销（§6）、显式姿态与替换纪律（§7）。后来加在同一条记录上的：铸 token 时的名字与 owner，以及机器绑定（prism ADR-0020）。

这份记录原本设定的实施顺序（信任模式开关与披露 → 密钥对握手与登记表 → 并入账号认证），前两步都按它做了，第二步的内容已被上面取代；第三步仍待 prism 的账户会话面。

## 诚实的语义代价

- **批准摘要是一次比对。** 记录处于 `pending` 期间，任何能到达 gateway 且知道别名的冒充者也可以处于 pending。操作员把登记表排队的那条摘要与节点打印出来的做比对；不做比对地点一下列表项只是点击，不是决策 —— 与未经验证的 SSH host key 是同一种失效模式。
- **查询串里的 token 就是日志里的 token。** URL 被代理、服务端和 shell 记录下来的可能性，远高于 header 或 body。所以凡是跨过它不能控制的东西去够 gateway 的部署，都欠一笔 TLS，也欠把访问日志看得和 token 一样重的谨慎。
- **在明文 `ws://` 上节点无法知道自己在和谁说话**，所以在可信网络之外的部署要求 TLS + 已验证的服务端证书；当配置要求 TLS 时，effector 应当拒绝明文 `ws://`。今天的测试用 `ws://`，这正是它属于前提而不是细节的原因。
- **token 防的是远程声称者，不是被攻陷的节点。** 持有这台机器的人就持有 token，就能成为这个节点。缓解手段是部署形态（短命、可替换的节点），不是更强的握手。
- **本裁决不主张的事。** 控制端不被当作对手：它是信任权威，节点约束不了它。让 token 不进入场地自己的表，为的是不制造泄漏面 —— 存在那里的 token，无论谁怀着什么意图，都可能从备份、dump 或日志里漏出去。
- **结果始终是不可信输入。** 认证改变的是谁可以当节点，不是结果的成色：effector 执行的是 AI 生成的代码，所以它的输出对控制端而言是数据，永远不是指令。那条裁决独立于本条，也不会被本条满足。

## Consequences（后果）

- **effector-protocol**：`Register` 携带 `{alias, carriers, class, machine}`；没有凭据字段，也没有 challenge 帧。token 走拨号。
- **prism**：登记表、四条端点、显式姿态，以及 §3 那张裁决表 —— 外加绑定：第一次已批准的注册写入 `machine`，此后每一次都必须来自它（prism ADR-0020）。认证数据是连接平面的关切（ADR-0017 §7）；在 aura 内也建一份，同一个决定就有了两个家。
- **aura**：节点活在**一个**池子里，每个域都借用它，带着准入时加好前缀的标签（aura ADR-0053）；placement 过滤那个池子。无论谁来配置都属于网关自身正确性的那部分，是替换纪律 —— open 姿态下别名顶替仍然允许、绝不静默，且 presence guard 带身份核对，被顶替的旧连接不得注销新持有者。
- **被取代的措辞**：`engine/src/lib.rs` 里“namespace is derived from the user credential at registration”。命名空间挂在账号上；token 只证明机器 —— 用户身份与机器身份是两根轴。
- **账号体系**：在 prism 的账户会话面存在之前，节点 token 由操作员用 curl 铸，它的 `owner` 就是操作员说的那个值。那是一个过渡形态，写下来是为了不被读成永久形态。
