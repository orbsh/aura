# 0031 — 远程摊位：两个层级、信任由所有权决定、投递是活的

> **语言：** [English](0031-remote-摊位.md)（主文档） · [中文](0031-remote-摊位.zh-CN.md)

**状态：** Proposed（2026-09-26）。同日经用户评审后修订：初稿的裁决——tier-2 审批
【更严】、三条密钥轴、事件词表的【授予仪式】——全部撤回，由下文论证取代。未开始
任何实施。

## 背景

今天的扩展面只有一种远程形态：远程 probe（`Body::RemoteProbe`，PLAN Phase 3）——
**远程执行**。probe 经 WS 拨入、按节点别名注册、执行控制平面写的代码：帧携带
`CodeRef{url, sha256}`（ADR-0027），执行发生在 probe 的常驻 session 里。摊位的
全部身份——定义、状态、调度——留在控制平面；远程端只贡献执行容量。

本 ADR 记录**远程参与**：摊位本身（定义、代码、存储）整体远程化，作为 realm 的
参与者协作——申报接口、接收其订阅的事件、应答调用。远程端自选语言与数据库。

动机说精确。aura/probe 限制语言和数据源，是因为一切都要放在能被检视的地方——代码
内容寻址、存储在 okm。远程摊位解除这个限制，而解除不是免费的：运维一个服务——
它的语言、它的数据库、它的可用性——**就是为自由付的税**。realm 对非内置语言和非
内置存储的态度：**不鼓励，不限制**。谁付得起税，谁解除限制。

用户给出的心智模型：aura 变得像一个 MQ broker，远程摊位是挂在它上面的服务——
传统微服务，消费订阅的事件、应答调用，带着自己的代码和数据库，broker 无法检视。
下一节要修正其中一点：这个 broker 的订阅是**活的**，不是持久的（见 §3）。

两个观察经受住了评审，支撑论证（每一条都可追溯到已落地的裁决，所以这是组装，不是
新机制）：

1. **actor 模型从未要求确定性。** realm 的语义是队列投递——自 PLAN 4.5c 起是
   per-(event, partition) 队列 + per-subscriber cursor，per-摊位 mailbox 模型
   已退役（ADR-0014）；按实例键串行、失败是值、观测面是投递记录和 dead ring
   （ADR-0012）。没有重放假设、没有可恢复随机性要求、没有延迟假设。人挂在对端不是
   协议特例：人就是 fluxen 摊位的非确定性执行，正如带自家 Postgres 的 Go 二进制
   是确定性执行。

2. **远程调用的机件已经建好。** 统一调用模型（Phase 3.5：`CallSpec{tier,
   timeout}` 在注册时静态声明、`CallSlot` 两级等待、`pending_remote` 关联）是
   目标无关的——今天服务 `RemoteProbe` 臂，删掉 CodeRef 构造就服务远程摊位（见 §5）。

初稿的第三个观察——"prism 客户端本来就是未注册的远程摊位，所以远程摊位必须
复用那个 mount"——撤回。两种形态本质不同（拨出且无需凭证 vs 拨入且按会话收口），
硬塞进同一个模子买不到东西；在连接平面加一种拓扑模式和"把平面劈成两半"是两回事。

## 决定

Proposed；标了 **裁决** 的段落是承重件。

### 1. 两个层级；信任问题跟着所有权走，不跟着能力走

把 realm 摊位拆成五个构件，逐个对照远程形态：

| 构件 | 本地摊位 | 远程摊位 | 移动了什么 |
|---|---|---|---|
| 类型定义 | register 时持久化 BoothDef；从持有的源码 introspect `interface_schema` | 注册时携带自申报 schema；持久化、路由装配、plan 解析路径不变 | 事实源："我检查了你的代码"→"你申报了接口" |
| 实例身份 | EventRouter + MQ 队列 + cursor | 活的连接集；事件到达时无端点连接=投递失败，不是积压 | 投递保证：持久→活（见 §3） |
| 存储 | okm 平面，`ctx.store` ns 寻址（ADR-0026） | 对端自己的数据库；控制平面看到有状态黑盒 | 审计面：realm 不再看得见摊位读了什么写了什么 |
| 驻留 | `Sessions` 注册表，每实例一个 VM（Phase 2.6） | 连接即 session；重连=再注册 | 故障模型："crashed"变成"disconnected"，不可区分也无需区分 |
| 调用 | run_job 派发 | 现成 `RemoteProbe` 臂删掉 CodeRef 构造 | 代码，以及随之消失的控制平面对"将运行什么"的知识 |

**裁决——信任是组织事实，不是密码学制品。** 初稿问"什么样的凭证链能让一个申报值得
信任？"评审的答案：这个问题对自己的服务直接溶解。审计另一个服务的代码不是架构问题
——同一个团队写的两个服务不是对手，指望 realm 去验证它们的行为，等于指望一个微服务
审计它同伴的源码。同一个给购物车加摊位、又把它的 emit 接进库存处理逻辑的所有者，
是在**做选择**；故意部署一个删除自家用户数据的摊位是蓄意破坏，而破坏是内部人问题
——任何凭证链都拦不住，也不需要拦。

所以两个层级问的是*不同*的信任问题，方向*相反*：

- **层级 1，远程执行（probe）：** 审批回答"信这台机器执行【我】写的代码"。内容
  是可机械验证的——内容寻址（ADR-0027）、逐字节可审计——而更重的凭证链属于
  【这里】，因为控制平面把代码送进了那台机器。
- **层级 2，远程参与（外部摊位）：** 审批就是部署决定本身。realm 所有者添加的是
  自己的服务；没有仪式，因为没有需要审批的外部性。tier-2 审批【更轻】，不是更严
  ——初稿的裁决反转。

| 层级 | 谁作保 | 方向 | 凭证 | 词表 |
|---|---|---|---|---|
| probe（执行级） | 控制平面（代码是它自己的） | 拨入 | 节点密钥对（ADR-0015） | 不适用（交执行结果，不发域事件） |
| 自有服务（逻辑级） | realm 所有者 | **拨出**：realm 连接远程 WS 端点 | 无——配置级身份（URL / 白名单），与任何微服务客户端相同 | 允许裸名（见 §4） |
| 用户会话（逻辑级，fluxen） | 人，经 prism 代理 | **拨入** prism 的 WS 平面 | device/user 锚（ADR-0017 §2） | 代理边界强制加前缀（见 §4） |

拓扑跟信任模型走：内网里的自有服务由 realm 拨出去连接——让端点可达是部署者自己的
问题，与微服务实践一致。浏览器拨不进去、也不该持有长期密钥，所以它拨入；realm 所有者
的风险在这里根本不存在，剩下的是*按用户收口*，prism 本来就在建（Phase 1 的流式那一半）。

### 2. 连接方向是推论，不是旋钮

**裁决——方向 = 所有权的拓扑表达。** 自有服务拨出；代理的会话拨入。初稿说反了的
推论在此纠正：

- 自有服务不需要凭证链。它们需要的只是一个地址。
- prism 的 per-event `auth` 块保留——它的消费者是 fluxen 这类拨入参与者，它收口的
  是【用户】的连接能 emit 和接收什么（网关按申报块拦截——谎报把自己锁在门外，是自损，
  不是信任）。
- 初稿的三条密钥轴（机器/工作负载/会话）撤回。自有服务根本没有工作负载身份——端点
  URL 就是身份。真实存在的密钥空间只剩两个：节点密钥对（传输层，ADR-0015）和 prism
  的 device/user 锚（会话，ADR-0017 §2）。为 (account, booth_type) 提议的账号平面表
  不建。

### 3. 投递是活的、同步的、跑在持久的连接上

**裁决——远程投递没有队列语义：无 cursor、无积压、无重放。** 路由到远程摊位的
事件在活连接上推送；无端点连接时，投递**失败为值**，落进投递记录 / dead ring 作为
失败证据——与 ADR-0012 给"不可路由事件"的观测面是同一套。持久队列（PLAN 4.5c）和
per-subscriber cursor 只服务 realm【内部】投递；初稿那句"scale-to-zero 语义白送"
撤回——远程参与者不是 scale-to-zero，它必须在运行，像任何微服务一样。

这就是税的具体化：远程摊位必须暴露一个 WS 服务端点并保持可达。草稿曾考虑"webhook
POST 起步、常驻 WS 作为效率升级"——撤回：两种形态的义务相同（都得有个监听的服务），
而半双工 POST 严格劣于常驻 WS 会话。远程线用 realm 自己的帧词汇表走 **CBOR**（自描述；
protobuf 这类 schema-first 格式被否决，因为参与者自选 schema 工具链）。拨入的浏览器
参与者豁免：JS 原生说 JSON，它面对的是会话 mount 而不是注册平面（见 §6）。

**裁决（2026-09-26 第二轮评审）——活性：realm 侧 ping，1–5s，无响应即断开。**
tungstenite 的读循环本来就对协议 Ping 自动回 Pong（RFC 6455 §5.5.2 "read is
responsive"），所以成本只是定时器和策略，不是新的协议机件：realm 按快节拍对
每条常驻拨出连接发 ping，Pong 缺席立刻关闭 socket，连接缺失之后的行为与冷
启动完全一致——事件失败为值，落投递记录。重连走指数退避；两次尝试之间的状态
就是【断开】——不存在"也许还活着"的中间态需要推理。这个政策站在微服务假设上：
拨出端点与 realm 同机房（所有者自己的网络），1–5s 的期限抓得住真故障、节拍也
便宜。同一条规则覆盖 emit 回传方向：realm 对拨出服务【不】施加 `auth` 块——
信任源是所有权（§4），给自己的进程设凭证等于查自己有没有入侵。

### 4. 词表：两条机械规则，没有授予仪式

**裁决——词表规则跟方向走。** 初稿的机制——限定名做默认、裸名靠授予、verdict/conflict
表扩展到事件名——全部撤回。EventName 注册表仍是 realm 全局事实（`order.created` 一个
名字一个含义），但保护它的是：

- **拨出（自有服务）：允许裸名。** emit `order.created` 的服务是所有者自己的代码；
  它 emit 的东西和路由表期望的东西不一致，是所有者业务的【内部】错误，与原生摊位拼错名字同级——不归 realm 管。自有服务之间的命名空间冲突是所有者自己的路由设计问题，
  与微服务实践一致。
- **拨入（代理的会话）：强制前缀。** prism 在浏览器 emit 的事件到达 realm 之前盖上
  会话账号（`<account>/<session>.…`），浏览器永远构造不出、也就永远碰不到内部裸名。
  接收方向 per-event `auth` 块已经在收口哪些名字能到达连接。**fluxen 的 emit 必须
  同样处理**——用户侧的摊位按拥有会话的账号限定，不按它的节点、也不按它申报的类型。

命名空间分配是代理边界上的机械字符串处理——不是审批决定、不是表、不是凭证。
前缀是 prism 的信封：入界盖章、出界剥章——且前缀的【形状】（`<account>/<session>.…`
是默认，不是定律）是 prism 侧配置，realm 看到的只是到达的名字。规则（拨入永远
得不到裸名）不可配置，实现它的字符串可配置。浏览器侧的词汇表两端都是裸名，它自己
emit 的名字路由回来时剥掉【本会话那一段】前缀再交付（别的前缀要么被 auth 块挡在
订阅匹配之外、要么原样保留——剥别人的前缀等于在出界方向反向击穿隔离）。出处不靠
名字承载：sender envelope（ADR-0017 §7）已经投递在 payload 里。前缀管隔离，
envelope 管出处，两件事不耦合。初稿留下的待议问题（"谁有权授予裸名"）没有残余：
没有人授予任何东西；拨出按所有权天然拥有名字，拨入永远得不到裸名。

### 5. 调用形态：invoke 跑在连接上，失败是值

不建新机制。远程类型在注册时声明 `CallSpec`（静态，Phase 3.5）：**hot**——调用方
挂在 oneshot 上，一个 WS 往返，超时是失败值；**cold**——会话背后是人（fluxen），
无截止期，调用方任务直接结束，应答帧经 `pending_remote` 关联、重新进入挂起的回合。
超时和"call dropped (sender gone)"都是经同一通道送达的失败【值】（ADR-0012）；
**没有重试、没有兜底，也不该建**——at-least-once 需要 §3 刚刚否决的持久投递，而对
有副作用的远程摊位做重试就是微服务的重复下单问题，那个问题归服务自己，不归 broker。
realm 的职责是诚实的观测面：投递记录和 dead ring。

### 6. fluxen 是验收测试

投递进浏览器的 fluxen 应用是本提案第一个真实消费者，也是最锋利的正确性测试：工作负载
（购物车页面的状态机）是远程的；它的确定性执行被换成了人（观察 1）；它拨入（方向，§2）；
它的 emit 被前缀锁住（词表，§4）；它经 auth 块接收域事件（prism Phase 1 流式那一半
——现在对本 ADR 是承重的，与被撤回的"同一个模子"框架不同）。

写给评审的验收判据：**自有的 Go 二进制和用户的浏览器都是"申报接口、接收事件、应答调用"
的参与者，共用一套协议——它们的差异恰好只有初稿混为一谈的两处：方向和词表规则。**
若出现任何【其他】差异（独立的注册路径、独立的帧语言、独立的观测面），层级边界就画错了。

## 诚实的语义代价

- **控制平面放弃知道什么在运行。** 代码不可见、存储不可见：审计面塌缩为投递记录、
  dead ring、加一份对端自报的申报 schema。对自有服务这损失不大——信任来自所有权
  （§1），但**知识**不来自所有权：远程摊位的拼写错误、版本漂移，只能靠失败投递
  事后发现，事前不可见。信任与知识的这个区分在信任简化之后依然成立，必须向集成者
  讲明。某些消费者（假定摊位语义可检视的 Gravity 提示词）需要重审；任何组件不得
  对远程参与者申报的正确性做假设。
- **活投递意味着宕机丢事件。** realm 内部订阅者可以消失几天再拿 cursor 续上；远程
  参与者宕机就丢了它的窗口——它观测失败，不重放。业务上真需要对外持久投递的人，
  超出了这套架构的射程。
- **说谎面还在，但很小。** 自申报的 auth 块、receives 集是承诺；auth 申报的执法仍然
  为真（按申报块拦截），漏报设计上不可检测。对自有服务，对自己说谎在结构上没有意义；
  对拨入会话，auth 块是用户自己的同意面，不是对抗面。
- **远程线是第二条线。** 注册平面说 CBOR，浏览器 mount 说 JSON：两种编码、一套协议。
  理由是信任模型确实不同（§4），但重复是真的。
- **本 ADR 不声称的东西：** 这不是让 realm *状态* 远程一致的提案。远程摊位的存储
  是它自己的；realm 对 ADR-0026/0027 给原生摊位的持久性、顺序、事务保证，一个都不
  提供。远程参与者知情地选择全部放弃——并且为这个选择付税（见背景）。

## 后果

- **顺序（拟议）：** (1) 拨出投递——注册携带端点 URL，realm 拨出并保持连接，事件推送
  和 invoke 跑在这条线上（派发臂 = `RemoteProbe` 删 CodeRef）；(2) prism Phase 1
  流式——按 auth 收口的接收那一半——落地 fluxen 需要的拨入面；(3) 词表前缀规则
  （prism 侧字符串处理）先于 fluxen 的 emit 开放。没有账号密钥设施、没有 verdict 表
  扩展、没有裸名授予的独立 ADR——那些是初稿的排序，取消。
- **实施时的触点：** realm 派发臂 + 拨出连接管理器（注册平面、CBOR）、注册帧管线、
  端点类型的 EventRoute 写入；prism 前缀盖章 + 出界剥章 + 订阅流式。全是小块，
  成本在上述决定里，不在代码里。
- **跨仓：** probe-protocol（拨出帧形；注册平面 CBOR 线）、prism（连接平面承载会话
  mount；盖章规则）、aura（realm + ADR 链）。
- **刻意保留的待议问题：** (b) fluxen 分级推进——是否先在拨入 mount 上
  dogfood，再走真实业务事件流；(c) 拨出端点要不要自己的姿势（`open`/
  `required` 式）限定 realm【去拨谁】——大概率就是一份白名单，但这个形状
  值得在某个地方写一句话。初稿的 (a) 心跳策略与 (d) 拨出 auth 姿态已在 §3
  【定案】（2026-09-26 第二轮）：realm 侧 ping 1–5s，Pong 缺席即断开，指数
  退避重连、中间态只有【断开】；拨出服务不带 `auth` 块——所有权即信任源，
  emit 回传同享此豁免。
- **跟进项（已落地 2026-09-26）：** prism `docs/PLAN.md` Phase 1.8 曾记录【初稿】
  的约束（tier-2 审批更严、三条密钥空间、词表闸门为先决条件）。其 DESIGN
  CONSTRAINTS 段已按本 ADR §1–§4 重写（信任由所有权决定、两个密钥空间、词表两条
  机械规则、活投递、拨出 CBOR 线）。
