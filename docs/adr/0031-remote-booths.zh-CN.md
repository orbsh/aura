# 0031 — 远程摊位：为什么不采用

> **语言：** [English](0031-remote-booths.md)（主文档） · [中文](0031-remote-booths.zh-CN.md)

**状态：** Accepted（2026-09-28）。这个编号只有一份历史：本 ADR 的早期草稿
（2026-09-26）曾提出远程摊位——realm 拨出连接外部参与者。经复核，该提案与项目
一条被遗忘的初始设定冲突；本记录是对它的裁决。实施从未开始，因此没有需要回滚的
东西。

## 背景——那个提案是什么

草稿把扩展面从 tier-1 远程**执行**（probe，`Body::RemoteProbe`，PLAN Phase 3）
延伸到 tier-2 远程**参与**：摊位本身——定义、代码、存储——住在外部服务里，realm
拨出连接到它的 WS 端点、在注册帧里带上端点地址、持有连接、ping 1–5s 探活、退避
重连、用 CBOR 说 realm 自己的帧词汇表。心智模型：aura 变成一个 MQ broker，远程
摊位是挂在它上面的微服务——消费订阅的事件、应答调用、带着自己的代码和数据库，
broker 无法检视。它的框架话术：运维一个服务「就是为自由付的税」，谁付得起税，
谁就解除语言/存储的限制。

承载那份草稿的两个观察在提案被否后依然成立，值得留档（见「什么幸存」一节）：它们
关于模型是真的，且支撑 tier-1。它们始终没有建立的，是**realm** 该为远程逻辑持有
socket——草稿在几轮评审里打磨那个机制，却从未质疑它本身。

## 提案遗忘的初始设定

**不存在远程摊位。** 逻辑归摊位，配置不是全局的，摊位自行决定访问方式。需要和
外部服务说话的摊位，在自己的代码内部、用自选的客户端完成——脚本体里的 HTTP 库，
wasm 摊位在 carrier 缺原生能力时的 WASI HTTP host。realm 的职责止于场的边界：
路由领域事件、应答调用、观测投递。

两种形态在每个要紧的轴上都不同：

| 关注点 | 远程摊位提案 | 初始设定 |
|---|---|---|
| 谁持有 socket | realm（拨出连接管理器） | 摊位自己的代码 |
| 端点申报 | 注册帧携带 URL | 什么都不越过 realm 的 API |
| 探活 | realm 侧 ping 1–5s、退避、DISCONNECTED 状态 | 摊位的问题，和它的任何逻辑一样 |
| 线路格式 | realm 定义的 CBOR 帧词汇表 | 对端服务说什么就是什么 |
| 失败语义 | 投递失败作为值进 dead ring | 普通的 handler 错误 |

## 决策

**裁决——对外访问是摊位代码的事，不是 realm 基础设施。**

1. **不建拨出设施。** realm 不为外部服务建连接管理器、不注册端点、不 ping。
   提案对摊位的五成分迁移不会发生：逻辑需要外部服务的摊位，把协调留在摊位
   内部——handler 代码按调用开连接（或按常驻 session 的生命周期持有——Phase
   2.6 的驻留是摊位对客户端状态的自选），解析对端说的一切，失败作为自身返回的
   值处理。
2. **语言 carrier 已经回答了这个问题。** steel/python/nushell 体自带原生 HTTP
   客户端；wasmtime 摊位要出 HTTP，需要的是 WASI HTTP host——这是 carrier 的
   运行时能力问题，不是 realm 的配置问题。往节点的 KDL 里加 `outbound_http`，
   等于让 realm 去担保一条它在语义上无法解读的连接。
3. **浏览器场景同样不需要远程摊位。** fluxen 用户的会话是**会话**，不是
   **摊位**：它住在连接平面（prism，ADR-0017），auth block、account/session
   前缀戳、流式订阅那一半已经在那里治理它。草稿的验收判据（「浏览器是远程摊
   位」）混淆了两个平面；浏览器是 prism 的参与者，realm 从来不会在一根自己没有
   拨出的 socket 背后看到摊位形态的东西。
4. **方向的镜像已经存在。** 至于**向外推送**的那一半——把场的事件送到非 realm
   消费者——建模指南（`docs/design/modeling.md` §outbound）已有形态：摊位 emit
   普通事件，外层平面的桥订阅它，aura 永远不知道 WS 存在。按调用的对外访问是同
   一立场的反方向：摊位行动，realm 只观测越过场边界的事件，仅此而已。

**税的论证为什么反转。** 草稿说运维一个服务「就是为自由付的税」。没错——而这恰恰
是**反对**该提案的论据：反正所有者要付运维税，realm 持有那根 socket 什么也买不到。
realm 没从中得到可观测性（投递记录和 dead ring 只覆盖场的事件；socket 里的内容
两种形态下都是不透明的），没得到信任（草稿 §1 自己的裁决：信任来自所有权，不需要
凭证链），反而为一根语义上无法检视的连接背上了探活策略。远程摊位是一个穿着客户
衣服的 broker。

**realm 仍然提供给远程端的。** Tier-1 远程**执行**——probe（`Body::RemoteProbe`，
ADR-0027）——不受影响，且是唯一的远程形态：控制平面把内容寻址的代码送进执行节点，
持有那根 WS 连接（节点密钥对，ADR-0015）。它成立，是因为控制平面是代码的作者；
这层关系，对一根 realm 只是「拜访」的第三方服务而言，没有对应物。

## 诚实的语义代价

- **对外调用对 realm 不可见。** 摊位的 HTTP 调用、它的延迟、它的失败、它对外部
  系统的副作用：都不出现在观测面上。这不是新增的不透明——脚本体本来就在控制平面
  跑任意代码——但本裁决把它说透，好让集成者不再期待 realm 提供对外审计。需要
  **记录**外部交互的摊位，应当 emit 事件来记录；模式是摊位的，日志是场的。
- **重试和幂等归摊位自己建。** realm 的「不重试，失败是值」立场（ADR-0012）平移
  过来：摊位调外部服务的重复下单问题归摊位所有——草稿把那个问题分给外部服务；
  现在的区别只是代码住在摊位里，作者看得见。
- **不需要新的词表规则。** 草稿 §4 的规则（拨出裸名、拨入强制前缀）消解了：没有
  摊位带着端点注册，就不存在拨出的命名面；拨入是 prism 的会话平面，戳规则照旧。
  仍然成立的词表裁决只有一条，且早已生效——EventName 注册表是全场事实，场内的每个
  摊位都用裸名，代理给它代理的东西盖戳。

## 什么幸存

草稿的两个观察是对的，留档：

1. **actor 模型从未要求确定性。** realm 的语义是队列投递（PLAN 4.5c；ADR-0014）、
   按实例键串行、失败是值（ADR-0012）。没有重放假设、没有可恢复随机性要求、没有
   延迟假设——挂在 prism 会话背后的人不是特例，正如带自家 Postgres 的 Go 二进制
   也不是。
2. **统一调用模型是目标无关的**（Phase 3.5：`CallSpec{tier, timeout}`、`CallSlot`、
   `pending_remote`）。它今天服务 `RemoteProbe` 臂，也会服务任何未来的远程目标——
   而这恰恰说明为什么不需要远程摊位那套**机制**来证明它：已存在的机制服务
   tier-1，此外没有谁要求搭车。

## 后果

- **prism `docs/PLAN.md` Phase 1.8：** 从草稿讨论记录下的 DESIGN CONSTRAINTS 块
  按本裁决改写——站得住的部分是 prism 自己的（会话平面、auth block、前缀戳、
  Phase 1 流式那一半）；拨出/CBOR/远程摊位注册那一半删除。probe mount
  （`/probe/<alias>`）和节点注册表属 tier-1，不受影响。
- **代码：** 无改动。`code_base_url` 保持节点级（ADR-0027 服务 tier-1）；远程摊位
  的臂本来就不存在，无需删除。两处写着「remote booth」实指 probe 的注释/字符串已
  改正为「remote probe」（`config/src/kdl.rs`、`realm/src/instance.rs`）。
- **wasm 对外访问，当某个 wasmtime 摊位需要时：** 这是 carrier 能力的任务（给
  wasmtime carrier 接入 wasi-http host，按摊位类型），不是 realm 配置的任务。
  在有人需要之前保持开放。
