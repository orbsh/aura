# 0038 — 事件面的消费者集合与身份（通配收窄、单字典、声明语义）

## 背景

`event-flow.md` §8 挂了四个问题：无 key（通配）订阅到底到达一个实例还是该类型的
每个实例；事件面要不要在类型字典（ADR-0040 分段下的 ns 30）之外自留一张订阅者身份字典
（旧 ns 33）；声明的粒度（逐事件 vs 类型默认）与路由行存什么；匹配到路由却没有真目标
时（`__default__` 兜底那一类）算什么。

本轮把每个问题重问成「这个形态在解什么约束」，而不是比较勾画出来的形态。

## 决策

**裁决——队列的消费者集合必须是闭集；无 key 订阅投递给该类型的单例实例；类型字典
只有一张、事件面借用它；声明逐事件给出目标解析、缺失即单例；任何 emit 不得静默
丢弃。**

### 1. 消费者集合闭集：通配投递给单例实例

- 游标行是「某个消费者的位置」，而保留水位的分母就是这些行——所以分母**就是**系统
  的保留承诺。承诺需要有限、可知、可回收的集合：闭集是语义的前提，不是效率属性。
- 有 key 的路由：partition = 实例 key，所以每个 partition 恰好一个消费者（碰撞例外
  见 ADR-0039 §1）。
- 无 key 的路由：partition = 单例。若广播到该类型所有实例，分母就变成「该类型当前
  活着的实例」——一个开集：每次新 key 的 emit 都激活一个新实例，而新实例的游标读作
  0，于是它重放该队列现存全部历史。水位被最新（或最慢）的成员永久钉住，「订阅」也就
  悄悄变成了「状态同步」。
- **裁决：** 无 key 订阅投递给该类型的单例实例。广播退役。
- **诚实代价：** 单例成为该类型通配流量的串行点。需要按 key 处理模式事件的类型应当
  声明有 key 的路由（或按扫描解析目标，即 Phase 4.13 的终态）——广播是那个需求的错误
  实现，不是它的更宽形式。
- **注：** `partitioning.md` §1 的原文本来就写着通配订阅绑定单例；实现比文档宽。这次
  收窄是回到文档，wildcard fan-out 测试随语义改写。

### 2. 一张类型字典：事件面自留字典退役，借用类型字典

- 逼出「类型名 → 小整数」这张表的需求是 ns 分配（ADR-0026：每个类型要一个定宽整数的
  数据 ns），不是事件面。ADR-0025 之后 meta 表与 mq 表同住一个 okm 实例，一张表足够
  两边用。
- 事件面自留字典（旧 ns 33）唯一不可替代的活是给**参与者名**（`"type/key"`，开放词汇）
  发号——§1 那个广播语义的副产品。广播退役后它没有存活理由。
- **裁决：** meta 面的唯一类型字典（ADR-0040 分段下的 ns 30；旧号 40，改名与反解析已
  落地）是唯一字典。事件面自留字典删除。mq 面的类型解析走 ns 30，游标键第三段 =
  `booth_id`（定宽 u32；裁决时叫 `type_id`）。
- **诚实代价：** `split_once('/')` 的症状免费消失，但 `bound_partition` /
  `routes_of_*` / compact 路径，以及以 `"cart/alice"` 字符串直调 mq 面的测试调用点，
  都要改；且 mq 的解析改为依赖 meta 的（同 crate 内的模块依赖，不是新的 crate 边）。

### 3. 声明语义：逐事件、缺失 = 单例、三种形状是三种机制

- `resolve` 回答的是「这个事件的 payload 指向我的哪个实例」——(type, event) 的函数，
  不是 type 的函数。同一类型的不同事件探的是不同 collection/index；类型级默认只在
  「该类型每个事件恰好同构」时才有定义，那是巧合，不是规则。
- 缺省值必须唯一确定语义：既无 `resolve` 也无 `key_field` 就是单例投递。再加一层
  「缺失 = 继承」会让同一个字段有两个读法（继承 / 单例）——属于声明-执行漂移那一类，
  不是风格问题。
- 三种声明形状是三种机制，不是三种语法：(1) 无目标信息 → 单例（纯函数式消费者）；
  (2) 目标随 payload → 零存储解析，而这是**完全没有 collections 的类型唯一可用的
  规则**；(3) 按索引扫描解析 → 有存储的类型（Phase 4.13）。保留 (2) 不是对 (3) 的
  优化，它让无状态类型可表达。
- 路由行存 collection/index/probe 的**名字**；解析住在 schema 主人一侧。存 slot/ns 号
  等于把位置当身份，schema 一改就静默改指向。
- **连带：** Phase 4.13 的未决问题（「逐事件命名 vs 类型默认 + 逐事件覆盖」）由本条
  关闭。

### 4. 投递完整性不变量：无静默丢弃

- 匹配到路由却没有真目标，意味着这个事实到达了无人处。它必须可观测，与「根本没有路由
  匹配」同级。
- **裁决：** (a) `__default__` 兜底退役——payload 缺声明的 key 字段 = 畸形事件，带原因
  标签落 dead ring；(b) 扫描零命中属同一类，同样记录；(c) 于是 dead ring 收三类：无路由
  匹配、`mq::append` 失败、无真目标。
- **诚实代价：** 兜底实例的历史行为消失。没有任何声明寻址过它，所以它的使用者按定义
  为零；真正失去的是那份静默，而这正是本条的目的。
