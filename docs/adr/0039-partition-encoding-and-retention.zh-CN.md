# 0039 — 分区编码与游标保留承诺

> **语言：** [English](0039-partition-encoding-and-retention.md)（主文档） · [中文](0039-partition-encoding-and-retention.zh-CN.md)

**状态：** Accepted（2026-10-02）——已落地（Phase 4.18/4.19，2026-10-02，commit `2d1fafb`）。
本条由用户要求的第一性推导得出；游标过期的形态是用户的裁决（2026-10-02：两个生命周期
不绑定，另加一个全局配置）。

**落地形态（2026-10-02）：** §1 `PartitionName`（ns 21）发号（`by_name` + `HighWater`，
反解析 `partition_name_of`）；`mq::Partition` 是结构化的切片（`Singleton` | `Named`），
单例永不进值空间；所有队列调用收 `&Partition`；`part_hash`/FNV-1a/`part_id_of`/
`part_hash_of` 已删，键宽收紧（MqData 20→16 B、MqCursor 16→12 B、MqHead 12→8 B）。
§2 `cursor_ttl` 是一个 `EngineConfig` 字段（KDL `mq { cursor_ttl "30d" }`，默认 30 天），
随每次 realm 构造带入；`MqCursor.last_active_ms`（v2 热尾）由 `advance` 落值；压缩谓词
让过期行退出分母，且「游标已低于水位」的惰性行由 `drop_cursor` 回收。

**一处超出裁决文本的读法（记录在案）：** 分母的判据落成 `mq::booth_subscribes`——
「该类型是否注册了**匹配**这个具体事件的路由（精确或通配）」。原先的精确 id 查表会把
**通配**订阅者静默排除出分母（它们的注册行带的是模式的事件 id），于是压缩会吃掉通配消费者
未消费的积压——这是实施 §2 时发现的「无静默丢弃」（ADR-0038 §4）违例。

**测试支持新增：** `age_cursor`（回填行的活跃时间戳）——`rewind_cursor` 现在落 NOW，
所以它钉住水位而不过期；TTL 路径由两者组合来测。

## 背景

分区 id 是键字段哈希（FNV-1a → u64），`0` 保留给单例分区；`MqCursor` 只有
`cursor: u64`。两者都记在 `event-flow.md` §7，都不是任何决策的主题。

有两个问题从未被问过：分区为什么必须哈希；实例消失后，系统对它的 backlog 承诺
什么。

## 决策

**裁决——分区成为代理词汇（字典发号，与事件名/类型名字典同一布局），哈希退役；
游标行按全局 `cursor_ttl` 配置过期，过期是把该行移出水位分母，永不删行。**

### 1. 分区身份：代理词汇，不是哈希

- 逼出哈希的是**位置**，不是文档给的 ADR-0002 合规论证：分区是
  `MqData = [event][part][time]`（以及游标键）的**中间段**，后面还有段。但 okm 的
  主键在**构造上**就是定宽——`KeyEncode` 遇到 `String` 字段编译期 panic（"the key
  encoding is fixed-width"，`okm-derive/src/key_encode.rs`）；变长字段只存在于**索引**
  fields 段，至多一个、紧邻主键前缀之前，且明确**不带长度前缀**（okm MODELING.md：
  长度前缀会让排序先按长度再按字节，毁掉字典序）。同一条定宽规则也管着 `Count`
  reduce 的 group 字段。所以在主键里内联分区字符串根本表达不出来：「自描述段」这个
  形态不是 okm 留给我们的选项。
- 文档自己的规则已经回答了这件事：开放词汇走**代理 id + 文本索引**（§7「词汇表不占
  真实 ns」）。分区值来自 payload 字段——它就是开放词汇。哈希才是那个例外。
- **裁决：** 分区成为与 EventName、BoothName 同构的代理词汇——一张 `PartitionName`
  字典（ns 21，见 ADR-0040 的分段）发定宽 `u32` id，带 `by_name` 文本索引与
  `HighWater` 水位，并保留反方向（id → 名）供运维用人话列出队列。`part_hash` 与
  FNV-1a 退役。`SINGLETON_PART = 0` 保留为哨兵 id，但变为**构造性不可达**（发号从 1
  起），且哨兵**离开值空间**：路由层用结构标记表示无 key 投递，不再比较魔法字符串。
- 为什么用这个形态而不是哈希：它把三个缺陷都变成构造性不可能——碰撞不会发生（号是发的，
  不是算的）；保留值不再与值空间共用名字空间（key 字面等于哨兵的有 key 实例再也不会
  别名进单例队列）；且映射可反查。
- 键宽：id 取 `u32`，与另两张字典同一布局；`MqData` 逻辑键 16 B、`MqCursor` 12 B、
  `MqHead` 8 B（今天是 20/16/12）。这些键本来就被 id 重发作废，缩宽是免费的。
- **诚实代价：** 每次 append、每次游标/backlog 操作多一次注册表 resolve——与 append
  已经在付的 `resolve_event_id` 同一成本类，且按路由那套处理：持久注册表是真相，内存
  映射是热面（§4 的模式）。字典每个见过的分区值一行、无过期（与游标行同一无界类别；
  GC 未裁）。
- **作废：** 本条 ADR 早先的「长度前缀段」方案在 okm 里不可实现，由本裁决取代。

### 2. 保留承诺：cursor TTL，与 idle_ttl 解耦

- 「实例可以死」需要一个**有界**的承诺。今天被驱逐实例的游标行留着，解读是「回来就
  重放」——但没有任何规则界定这个承诺持续多久，而这个承诺正是决定该分区 `MqData`
  能留多久的东西。
- 两个生命周期不是同一个生命周期：`idle_ttl` 以秒计（热实例的驱逐），游标的作废视界
  以天计。绑定两者等于让一个秒级事件决定一个天级的数据承诺。
- **裁决：** 全局 `cursor_ttl` 配置（一个 `EngineConfig` 值，落到 `Realm` 字段，与
  `idle_ttl`/`code_base_url` 并列；KDL 里按 duration 字符串写，如 `"7d"`）。默认取
  **有限值**（30d）：「永不」作为默认等于把无界增长设成默认值。不给 per-type 覆盖——
  分母是对可能来自不同类型的行做 `min` 比较，按类型分叉视界会把不同承诺混进同一次比较。
- **机制（过期 ≠ 删行）：** 过期的含义是该行退出水位分母，从而允许压缩越过它——积压
  作废，这就是承诺的实现。改为删行会让游标读回 0，而 `backlog(after = 0)` 会重放现存
  行：游标原本**领先**于水位的实例会重新消费已经消费过的行——重复投递。物理删除只留给
  「游标已低于当前水位」的行（它们的 backlog 已不存在，删掉无从重放），这也给游标行一个
  收敛的清理规则——否则每个见过的 key 都留一行。
- **行：** `MqCursor` 增 `last_active_ms: u64`（热尾追加，`#[ok_layout(version = 2)]`，
  照 `BoothDef.encoding` 先例），语义 = 最后一次 `advance`（skip-to-now 算活跃）。
  哨兵规则：`0` 永不参与过期判定——旧行把缺失字段解码为 0，没有这条规则，新代码第一次
  运行就会让全部行瞬时过期、所有积压当场作废。
- **判定时机：** 压缩时的谓词（emit 路径算水位时本来就枚举该分区的游标行），不是后台
  守夜进程——保留决策只在新行到达时到期。timer wheel 只在可选地回收惰性行时才用。
- **契约：** 冷消费者在 `cursor_ttl` 内未推进，其积压作废。返回时它从自己的游标读现存
  行继续；被压缩掉的那段永久丢失。丢的是 backlog，永远不是状态——状态住在类型的
  collections 里，队列不承担状态的持久职责。
- **不做配置校验**（「`cursor_ttl` 必须显著大于 `idle_ttl`」这条方向性约束写进文档即可）：
  `idle_ttl` 有 per-type 覆盖，全局断言会误伤。
