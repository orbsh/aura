# 0040 — 框架键空间分段：事件面 2x，meta 面 3x（ADR-0026 §1 修订）

> **语言：** [English](0040-keyspace-bands.md)（主文档） · [中文](0040-keyspace-bands.zh-CN.md)

**状态：** Accepted（2026-10-02）——已落地（`#[ok_ns]` 改号随 Phase 4.18/4.19，
2026-10-02，commit `2d1fafb`）。用户裁决：分段为 `2x` 与 `3x`，不用 `4x` 段（2026-10-02）。

**落地形态（2026-10-02）：** `crates/realm/src/mq.rs` 声明 ns 20–25（EventName 20、
PartitionName 21、MqData 22、MqCursor 23、MqHead 24、EventRoute 25），
`crates/realm/src/meta.rs` 声明 ns 30–32（BoothName 30、BoothDef 31、CodeBlob 32）；
事件面自留的订阅者字典已删除（ADR-0038 §2），不占号位。它隐含的**清除**是既有部署上的
**运维动作**（`30–35`/`40–42` 下的旧字节不得被重新解读）——新库没有可清除的东西，本仓的
测试每次构建全新的库。

## 背景

框架低位块是按历史长出来的：事件面拿走 `30–35`，meta 面 `40–42`，号位记录的是各表
到来的先后（`EventName` 最早、`CodeBlob` 最晚）。号里没有任何东西表达「这张表属于哪个
面」，而低位块已经漂到了第三个十位。

修正的时机就是现在：ADR-0039 的分区切换会重发分区 id，ADR-0038 §2 会重发每个游标行里
的类型 id——事件面的每一行本来就已经失效。搭同一窗口做重新编号，不额外增加破坏。

## 决策

**裁决——框架低位块分两段：ns `20–29` = 事件面，ns `30–39` = meta 面。段内的表序是
概念序（词汇 → 数据 → 位置 → 注册表），不是历史序。**

### 布局

| ns | 表 | 面 |
|---|---|---|
| 20 | EventName —— 事件词汇（`by_name` 文本索引） | 事件 |
| 21 | PartitionName —— 分区词汇（ADR-0039 §1；`by_name` + `HighWater`） | 事件 |
| 22 | MqData —— 事件数据 + live `Count` reduce | 事件 |
| 23 | MqCursor —— 订阅游标（第三段 = ns 30 的摊位 id） | 事件 |
| 24 | MqHead —— 分区写头（序列发号器） | 事件 |
| 25 | EventRoute —— 持久订阅注册表（`by_booth` 索引） | 事件 |
| 30 | BoothName —— 唯一类型字典（同时分配数据 ns `100+id`） | meta |
| 31 | BoothDef —— 一行一个摊位类型 | meta |
| 32 | CodeBlob —— 内容寻址的代码字节 | meta |

预留：`26–29`（事件面的空段）与 `33–99`。`BOOTH_NS_BASE = 100` 不变——摊位类型仍从
框架块之上分配。

### 必须写明、而不是让人撞见的后果

- **新 meta 段落在旧事件面用过的号上。** ns 30 上的新 `BoothName` 行会把旧的
  `EventName` 行解码成类型名——正是「把旧数据读成新数据」这条永不复用规则要防的事。
  所以本次重新编号只有在**整个低位块被彻底清除**的前提下才安全。
- **这个清除比「mq 字节是转瞬即逝的」大一圈。** 已持久化的摊位定义与代码 blob 一起
  没了：部署方要重新注册类型（代码 blob 可由源码重新导出，定义要重新上传）。接受——
  引擎处于前生产阶段（Phase 4，单节点），ADR-0018 已立 clean-break 先例——但它记在
  这里，因为它是分段变更真正的代价。
- **另一个选择，留档**：把 meta 段放到旧事件段之上（如 `36–38`），使新号与任何旧号都
  不重合——那样旧定义行可以被读一次并改写进新号（迁移仍可能）。未选：分段整齐优先于
  一条目前没有任何部署需要的迁移路径。
- **两段是密的——不携带任何旧空洞。** 退役的订阅者字典（ADR-0038 §2，旧 ns 33）不给
  号位：在彻底清除下它的旧号是死的、新段里的位置是全新的。永不复用规则由「清除」满足；
  此布局之后，号位仍然永不复用给另一张表。
- **旧号 `30–35` 与 `40–42` 永久作废**：它们描述的布局已不存在。代码注解、event-flow
  §7 表与 ADR-0026 §1 迁到新编号；记录旧号的历史文档（更早的 ADR、PLAN 日志条目、
  描述性设计页）保留其落笔时的表述。

## 后果

- **代码**：`crates/realm/src/mq.rs` 的 `#[ok_ns]` 注解（30–35 → 20–25）与
  `crates/realm/src/meta.rs`（40–42 → 30–32），加上上面两个新号。随 Phase 4.18/4.19
  落地，不提前——清除与重编号是同一个操作。
- **文档**：`event-flow.md`/`-en.md` §7 是权威表（双语）；ADR-0026 §1 加日期化的
  Update 注；ADR-0038/0039 凡提到号位处随新编号。
- **`ns-layout.md`/`ns-layout-en.md`**：指针页，不提号位，无改动。

## 更新——数据面版本标记（2026-10-12）

低位块清除的运维动作此前依赖运维者的记忆：存储里没有任何东西说明它是哪个布局写的，
未迁移的部署会把旧行静默解码成新表（重编号把新 meta 段 30–32 放在旧事件面的号上——
正是号位永不复用纪律要防的「读旧成新」失败）。清除动作现在有了**闸门**：

- **ns 26** 一行原始键值（`b"plane-version"` → `u32` BE 日期戳；26 本是空段，
  该行是**标记**不是表——无 derive、无 schema，这个 ns 不再承载别的东西）。
- 新库首 boot 种子；此后每 boot 校验。不匹配 = **boot error**，报出两个版本号与
  清除指引（删数据目录；旧段的摊位定义与代码 blob 一并作废——重新注册类型；
  状态住类型的 collections，清除时一并重置）。
- `PLANE_VERSION` 随任何旧库无法解码的 `#[ok_ns]`/键宽/表形状变更而 bump——与
  §7 表同步是同一条纪律，同一次提交多改一行。

代价记录：一个标记行 = 每 boot 一次点读 + 占一个 ns；换来的是「记得清除」变成
「节点拒绝带病启动」。A3 运维动作以错误信息里指引的形式存续，由看见 boot 失败
的人执行。
