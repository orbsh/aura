# ADR-0049 — 资源是一份授权，不是一份快照

状态：已接受（2026-11-17）。取代 ADR-0048 的声明、注册表与版本三节（§1–§3），以及其中所有
"venue 持有指针"的说法。

## 背景

ADR-0048 给 venue 派了三件事：携带声明、按 `(owner, kind, seq)` 维护资源注册表、为每次发布记录一个
版本，好让坏写入靠"不推进指针"撤销。三件都错了形状。

**开跑前固定的声明没人能填。** booth 需要什么数据是**代码跑起来之后**才决定的——effector ADR-0003 §5
的原话就是"a task discovers what it needs while it runs"。于是跟着调用走的那张表注定是空的；脚本想要
第二个文件就得重新声明、重新派发。

**版本指针是抄 store，而且可能抄错。** git 的 ref、对象存储的版本、rustic 的快照，各自已经是一份带名字
的历史。venue 再存一个指针，多出一样**可能出错**的东西（两边会漂移，而回滚时赢的是错的那个），换来的
是 store 早就能做好的事。

**一个资源一行会把注册表变成更慢的桶。** 地址空间既然是 S3 形状，脚本自然会给自己要的东西起名
（`org/repo`、`builds/out.tar`）。给每个名字登记一次，等于把 API 变成审批队列，而"任务能叫什么"的
瓶颈落在了操作员身上，不在脚本身上。

## 决定

**venue 授权，节点搬运，store 记住。**

1. **一种 kind 一份授权。** 授权是 `(kind) → { base, mode, credential }`。键就是 kind；租户不是行，
   是本 venue 拼出来的前缀。于是**一个共享存储，一行授权服务所有人**。

2. **kind 是机制，不是存储。** `KINDS = ["git", "object", "archive"]`。`object` 是一个 blob，走 S3
   形状的线协议；`archive` 是增量仓库（今天 rustic，明天任何等价物）；`git` 是有自己引用词汇的仓库。
   `image` 删掉——容器**是什么**属于节点声明的环境（effector ADR-0003 §1，以及它那条「the image is the
mount」的后果），不是脚本读的数据。`volume` 删掉——
   "活过一次调用的目录"是节点本地缓存策略，一行描述不了一台机器。

3. **有效根是拼出来的，不是调用方给的。** `material(tenant, kind)` 回答 `<base>/<tenant>/<kind>`。
   节点把脚本自己的 `remote`（`org/repo`、`a/b.bin`、`project-x`）拼到这个根上，之前先校验它是相对名：
   不含 `..`、不以 `/` 开头、不含反斜杠。**前缀之所以存在，是因为节点在拼它**；store 无法把凭证限定到
   前缀，所以这是命名规则，不是隔离边界。

4. **脚本命名，节点搬运。** `ctx.resource({op, kind, remote, mount?, ref?})`：`get` 取到 `mount`
   （默认 `<root>/<remote>`），`publish` 把同一路径推回去，并回答 store 铸出的引用（`branch@sha`、
   ETag）。git 和 curl 由节点跑；脚本不装客户端，凭证也到不了它手里。

5. **没有版本表、没有 `Synced` 帧、没有指针。** 发布的引用回给脚本。撤销是 store 自己的事：git revert、
   rustic 的快照、开了 versioning 的桶。

6. **清理跟着节点，不跟着时钟。** 节点 materialise 过什么会被记下来，在进程离开时删除（`Drop` 守卫，
   所以租约到期、断连、报错三个出口都清）。

## 后果

- **三张表变两张**（`grants` 在 ns 36，`secrets` 在 ns 38），ns 37 退休。注册表是"每种 kind 一行"
  加它的凭证，管理面只剩两个路由：声明授权、读授权。
- **脚本可以在自己那片里随便命名。** 这是目的，也是代价：venue 不再知道某个租户写了什么，
  "这个 owner 有什么"是 store 的问题，不是我们的。
- **泄漏一份凭证等于泄漏整个 store，不是一片。** 前缀防的是撞名，不是访问。这条界限写在这里，
  免得日后有人把 "cannot escape" 读成 "isolated"。
- **object 的写入失去撤销能力**，除非桶开 versioning。那是一个运维开关，比一张指针表便宜，
  也不会和 store 自己打架。
- **`archive` 已声明但还不能搬。** 节点按名字拒绝它，直到传输代码存在；一份用不了的授权只会在第一个
  任务上才被发现。
- **数据库作为资源仍然搁置**（aura PLAN 的 Ideas 节）：SQL 文本进、JSON 出确实符合形状，但"第二个状态
  存储 + booth 之间没有顺序"是另一个决定。

## 被否决的方案

- **保留声明但两边都写（调用上和 ctx 上都有 `resources`）。** 同一件事两种说法；运行时那种严格更强，
  静态那种就是多余的重量。
- **保留 `seq` 再加一个 `name`。** 一个没人能读的数字，加一个必须与之同步的名字，是一行两个标识。
- **`kind: "s3"` 加一个 `incremental: bool`。** 这面旗不是一根轴：rustic 就是"增量使用的对象存储"，
  节点必须把旗翻回机制——同一件事两个名字。凭证形状也随机制不同（`object` 签 `ak:sk`，rustic 还要
  仓库口令），所以 kind 必须说清是哪一种。
- **网络文件系统作为一种 kind。** 可重现性最差：读到的是挂载那一刻远端的样子，这次运行的任何东西都
  无法重复。
- **按 executor 引用计数做清理。** 共享资源在一个 executor 退出时被删，会打断另一个还在读的；
  进程生命周期才是诚实的单位。
