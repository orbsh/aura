# 0054 — 机器 id 是地址，标签是请求

> **语言 / Languages:** [English](0054-a-machine-id-is-an-address.md) (primary) · [中文](0054-a-machine-id-is-an-address.zh-CN.md)

**Status:** Accepted（2026-11-20）

## Context（背景）

placement 只能按标签过滤（ADR-0053，`Placement::Labels`）。标签是人话 —— `u1:MyLaptop`、`site:home` —— 随节点 token 一起铸（prism ADR-0020），在准入时加前缀。作为**请求**的词汇，这是对的：人或者模型说"在我的笔记本上跑这个"，由场地去弄清楚那是哪台机器。

作为**寻址**的词汇，它错了，而且是三种已经存在的情形：

- **必须落到同一台硬件上的重试。** 某一步在某个盒子上跑过，文件留在那里。下一次调用必须去那个盒子，而标签是人随时可以改的一个词。
- **已经把词解析掉的调用方。** 操作员手里就有机器 id（prism 会报），或者调度器自己有一张"哪台机器上有什么"的表。它有 id，没有理由再去学 alias。
- **"不是控制端的那台机器"。** 有些定位是关于人拥有的硬件本身，而不是他们命名过的任何东西；而空的标签列表已经表示 `Any` —— 于是要指定"就是这台盒子"，唯一的办法是给它编一个标签。

与此同时，机器 id 已经存在、也已经在报告：节点说明自己是哪台机器（effector ADR-0006），注册表把 token 绑到第一个出示它的机器（prism ADR-0020），池子也能回答某个 id 上跑着哪些 alias。

## Decision（裁决）

### 1. `Placement::Machine { machine }` —— 一个盒子，按它报告的 id

用 effector ADR-0006 的机器 id 来寻址。作业信封多一个 placement 变体；场地解析它的方式与解析标签完全相同，且在领域存在之前（ADR-0053 的规则不变）。

id 寻址的是盒子，不是进程：**跑在那台机器上的每个 alias 都可达。** 一台笔记本上两个节点（比如一个常驻的、一个容器的）是同一块硬件后面的两扇门，在这里替它们做选择，等于让过滤器决定一件它看不见的事。

### 2. 空 id 什么都不寻址

`Placement::Machine { machine: "" }` 在任何领域存在之前就被按名拒绝。它不放宽成 `Any`，也不变成"那些说不出自己是谁的节点" —— 那种读法会让缺失的身份获得一个组的权力，而且是"不说哪台就要硬件"的一条路。

### 3. 拒绝时列出 id，因为调用方是按 id 问的

`DispatchError::NoSuchMachine` 把场地里每个节点以 `alias=machine` 列出。按 id 问的调用方需要的是**这里有哪些 id**；它从没提过的标签，在唯一一条必须告诉它下一步试什么的消息里只会是噪音。

### 4. 两个变体互不包含

标签可以匹配多台机器 —— 那是过滤器，匹配到多个是对的。id 匹配一个盒子或者什么都不匹配 —— 那是地址。把两者合成一个，就会逼其中一个按另一个的方式行为：要么 id 变模糊，要么标签变精确。

## 否决的方案

- **`Placement::Alias { alias }`。** alias 是那扇门的名字，改名正是它的用途。一个人给笔记本改名就跟着变的地址不是地址，只是短一点的标签。
- **把机器 id 放进 `ToolCall.executor`。** executor 指的是**作业自己声明的实例**（`type/key`，ADR-0042），硬件不是类型的一部分。它还会让声明集合取决于池子里恰好有什么，而那正是 ADR-0051 要避免的耦合。
- **在场地内部把标签解析成机器 id，两者都当 id 用。** 那样两台机器上同名标签就不再是合法的过滤结果，而每一次改名都会悄悄改掉所有用过那个词的地址。
- **让空 id 匹配未识别的节点。** 缺失的身份会获得一个组的权力：`machine: ""` 会成为唯一一条通向"所有分不清的盒子"的 placement。

## 后果

- **重试可以被钉住。** 知道工作把文件留在某台盒子上的调度器可以这么说，而不会被一次改名悄悄搬走。
- **用户永远看不到 id。** 他们输入和阅读的是名字；管理面报告 id（prism ADR-0020 的列表），而人组合出来的任何东西都不需要它。这个不对称就是重点：名字给人，id 给不能猜的机器。
- **换了 alias 回来的机器还是同一个地址** —— alias 是门，id 是盒子。
- **`JobOutcome.nodes` 仍然列 alias** —— 结果是关于门的；调用方需要 id 时，可以经注册表 join 出来。

## 测试

- `crates/engine/tests/dispatch_job.rs` —— `a_machine_id_addresses_the_box_whatever_its_alias_is_now`（可达集由 id 构造：另一台盒子被过滤器拒绝）、`a_machine_no_node_is_on_is_refused_and_names_the_ids_that_are_here`（领域存在前拒绝，列出 `alias=machine`）。
- `crates/realm/src/pool.rs` —— `aliases_of_machine` 返回该盒子的每个进程（有序）；空 id 返回空。
